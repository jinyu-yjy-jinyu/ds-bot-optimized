# 工作分组的工作区与批量模型

- 日期：2026-11-12
- 相关：`docs/plans/2026-11-04-sidebar-sections.md`、`docs/plans/2026-10-27-private-bots.md`

## 为什么

组里的 Bot 常常属于同一条业务线，它们本来就该在同一个目录里干活。现在只能在每个 Bot 的
设置里、或每个群聊里分别指定工作目录，Bot 一多就要逐个配一遍；模型也一样，只能一个个改。
分组本身已经存在（侧栏「分组」），它只是还没有工作区。

## 已定的行为

- **分组带一个工作区。** `state.sections` 的每一项新增可选字段 `workDir`（绝对真实路径）。
  没有这个字段的分组不改变任何行为，因此升级不会移动已有团队的文件。
- **解析优先级**（`folders.js` 的 `workDirOf`，唯一的解析点）：
  1. 群聊自己的 `workDir`；
  2. 群聊里某个成员自己选过的目录（`room.memberDirs`，值为空表示总工作区）；
  3. Bot 自己的 `workDir`；
  4. Bot（或该群聊）所属分组的 `workDir`；
  5. 总工作区。
  也就是说：分组是组内所有 Bot 的默认目录，单个 Bot 和群聊仍然可以覆盖它。
- **新建分组就是新建工作区。** 在设置里新建分组时，默认在总工作区里新建一个以分组命名的
  目录，并把它注册成 DSH 工作区；也可以沿用总工作区（清空分组目录）或改指到一个已有目录。
- **改目录会让会话换到新目录。** 和改总工作区一样：空闲的会话立刻换，正在跑的回合在下一步
  换；旧的目录和里面的文件不动。
- **校验沿用既有规则。** 分组目录必须是已存在的绝对路径，不能与隐私 Bot 的目录重叠；失败时
  分组本身（名字、颜色、成员）保持不变。
- **批量设置模型。** 设置里的「Bot models」页可以勾选多个 Bot，一次把它们设成同一个模型。
  只列 DSH 提供的模型；跑在本地 agent CLI 上的 Bot 不能被批量改（它的模型属于那个 CLI，换
  运行方式需要在它自己的设置里确认），这些 Bot 会被跳过并列出原因。
- **主 Bot 不参与分组。** 第一个主 Bot 始终是侧栏顶部的大卡片、永远不属于任何分组，它用总
  工作区；这沿用分组的既定行为。

## 不做什么

- 不新建一套「组」实体。侧栏分组就是组，避免出现第三套分组概念（已有分组、群聊）。
- 不嵌套子分组，不把分组目录做成独立的数据根。
- 批量设置不跨运行模式，也不改团队的默认模型（默认模型仍在设置里单独设）。
- 删除分组不删除磁盘上的目录，也不删除组内的 Bot 或群聊。

## 已知限制

- 写给 Bot 的界面文案里，分组目录是「默认目录」：Bot 自己设过目录时分组目录不生效，设置页
  会显示它自己的目录。
